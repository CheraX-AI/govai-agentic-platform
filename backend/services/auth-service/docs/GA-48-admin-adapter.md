# GA-48 registration Admin adapter contract

Current prototype decision: the user accepted the documented group-wide
administrative authority. [Isolated lifecycle tests](GA-48-registration-lifecycle.md)
now exercise the scoped group model. Historical per-operation isolation tests
remain FAIL_UNSAFE. The adapter now requires a
[server-configured registration group](GA-48-group-adapter-config.md);
no public endpoint or production permission is enabled by that acceptance.

Implemented 2026-10-29 as an isolated library. No route, environment loading,
Keycloak setting, database, login or background worker is wired to it.

`internal/registration/admin.go` defines the constructor-injected service boundary.
`internal/keycloak.NewRegistrationAdmin(RegistrationConfig, *http.Client)` implements
it using the pinned [Keycloak 26.8.1 Admin REST API](https://www.keycloak.org/docs-api/26.8.1/rest-api/index.html).
The caller must supply only administrative service-account configuration, separate
from future password-login clients. There is no password-grant implementation.

| Method | Exact permitted operation |
| --- | --- |
| `CreateDisabled(ctx, validatedRequest, operationID)` | POST users with canonical username/email, initial non-temporary password, enabled=false, emailVerified=false, VERIFY_EMAIL, the single internal operation marker and exactly one configured group path. Returns the subject from a validated Location. Never sends NIC/name/phone, role mappings or caller-selected groups. |
| `FindOwned(ctx, operationID)` | GET users with a fixed marker query, max=2 and full attributes. Accept exactly one exact marker match; zero is not-found, multiple or mismatched results require operator reconciliation. Never searches/adopts by email. |
| `ReadOwned(ctx, subject, operationID)` | GET one subject and verify its returned ID and exact single marker value. Return only subject/enabled/emailVerified, not the upstream representation. |
| `EnableOwned(ctx, subject, operationID)` | Read ownership, then PUT only enabled=true. Already enabled is a no-op. Caller must have durably completed the owned profile first. |
| `SendVerification(ctx, subject, operationID)` | Read ownership; require enabled, skip if verified; PUT send-verify-email with configured client, exact redirect and explicit lifespan. Success means request accepted, not inbox delivery. |

Internal operation IDs and subjects are restricted to 1–128 ASCII letters, digits,
underscore or hyphen. The operation marker is generated by the trusted service,
never public JSON. Returned subjects belong only in the restricted profile/journal.
No arbitrary update, delete, credential reset, role mapping or account-link method.

Before create, orchestration must durably reserve the operation/NIC; after create
it must record the subject/profile and only then enable. This adapter supplies no
durable journal, locks across processes, idempotency, recovery or uniqueness. A
not-found search after an uncertain create does not prove creation never happened;
do not release reservations or blindly retry. An unsafe/missing Location after 201
is also ambiguous. Multiple identities, mismatches and uncertain state stay pending
for reviewed recovery. Ownership read/update is not atomic: the marker must be
immutable to end users, and server-side privileges must prohibit unrelated-account
mutation. Go checks alone cannot restrict a broadly privileged credential.

## Transport and service-account token custody

Configuration is explicit, with no defaults or process environment reads. BaseURL
must be HTTPS with an optional simple fixed deployment prefix, no trailing slash,
credentials/query/fragment/escaped path. Realm is a safe path segment. The action
redirect must be a fixed HTTPS URL without query/fragment; owner approval and the
matching Keycloak allowlist are deployment prerequisites, not inferred here.

Supply a standard `*http.Client` backed by `*http.Transport` (or nil Transport for
the standard default). The adapter clones both, preserves trusted roots, removes
cookies, overrides redirect handling, bounds response headers to 16 KiB, and rejects
TLS verification bypasses/custom TLS dialers or verification callbacks. Opaque
RoundTripper wrappers are rejected. Use a non-instrumented transport; external
HTTP tracing/APM must not capture headers/bodies. Close the adapter at shutdown to
release idle connections. There is no HTTP exception, even for local tests.

CallTimeout must be positive and at most 5 seconds. Each public operation has one
shared total context deadline across token lookup, ownership read and mutation;
caller deadlines/cancellation may shorten it. MaxResponseBytes is required, from
256 bytes to 1 MiB inclusive, applied to every decoded/decompressed response before
JSON parsing. Recommended starting value: 64 KiB. Responses are closed on every
path. Redirects are returned as failures and never followed.

Token retrieval uses form-encoded client_credentials, client_id and client_secret
at the fixed realm token endpoint. It caches only an access token in process
memory; never exposes it through the interface. Token fetches are serialized with
cancellable waits; no goroutine refreshes tokens. Valid Bearer tokens require a
positive expires_in at most 24 hours. Expiry is measured conservatively from fetch
start, less configured TokenSkew (0–60 seconds); expired/too-short/malformed tokens
are not cached. A 401 invalidates the token used, but does not replay the failed
operation. A later independent operation may obtain a new token. There are no
automatic retries of token requests or mutations and no retained passwords.

Creation Location accepts absolute same-origin URLs or root-relative paths only,
under the exact configured users path with one safe subject segment. Reject
alternate realm/origin/scheme, credentials, query/fragment, escapes, dot segments,
network-relative paths, extra segments and missing/multiple Location values.
It is parsed, never fetched.

## Safe outcomes

Errors are `*registration.AdminError`: fixed Code and UnknownOutcome only. They
never wrap transport exceptions or expose bodies, URLs, credentials or PII.

| Code | Meaning |
| --- | --- |
| admin_invalid_input | Invalid constructor/input/action state; no corresponding mutation attempted. |
| admin_duplicate | Create returned 409; do not update or adopt the existing identity. Public orchestration must hide account existence. |
| admin_policy_rejected | Admin operation returned 400: generic policy/input rejection, not a recognized password-rule message. For create, UnknownOutcome=true until live atomicity is proven; never turn raw upstream text into field errors. |
| admin_permission_denied | Admin 401/403 or token endpoint 400/401/403. No retry/replay. Review configuration/permissions. |
| admin_not_found | Admin 404 or empty marker search; never permission to recreate after an uncertain attempt. |
| admin_ownership_mismatch | Mismatched/multiple marker results or wrong returned subject. No dependent write. |
| admin_canceled | Canceled before dispatch or during token/read operations; no new mutation dispatched by that phase. |
| admin_upstream_failure | Token/read network/TLS/status/size/parse failure. No credential details. |
| admin_ambiguous_outcome | Mutation transport failure/timeout/cancellation, oversized/unreadable response, unexpected status, or unsafe create Location. UnknownOutcome=true; reconciliation required. |

UnknownOutcome describes this transport call, not an entire durable workflow.
For example, a canceled ownership read says nothing about an earlier create.
No exception is evidence that a distributed identity transaction rolled back.
Policy messages are not parsed; real Keycloak behavior needs separate tests.

Credentials, secrets and transient payloads stay only in memory for the bounded
call; no logs, queues, files, tracing, metrics, raw-error responses or persistence.
Admin, config, identity and existing request values redact standard formatting,
JSON and structured logging. This does not protect callers logging field accessors,
transport instrumentation or raw bodies. Go cannot guarantee memory zeroization.

## Evidence and next step

Update 2026-10-29: the separate [live permission experiment](GA-48-permission-experiment.md)
has completed. Both creation-capable models allowed unrelated/admin account
mutation; an owned-user-only scope blocked account creation. The present design
therefore fails its permission release gate. Lifecycle/password-policy/SMTP tests
remain pending; do not enable public registration or grant these permissions in GovAI.

The later [group experiment](GA-48-group-permission-experiment.md) demonstrated
group-bearing creation with narrower external-account access, but retained control
over every registration-group member's credentials. Group-bearing creation
was initially in the harness only; the adapter now emits the same configured path
representation. Its new payload is covered by synthetic TLS tests, not a new live run.

Synthetic tests use `httptest.NewTLSServer` and its trusted test client. They cover
construction, cache serialization/expiry/invalidation, token failures, ownership,
request allowlists, TLS rejection, redirects/Location validation, cancellation,
timeouts, body caps/read failures and redaction. They do not prove actual Keycloak
permission scoping, password-policy enforcement/atomicity, marker search/profile
configuration, default roles, partial-update semantics or SMTP delivery.

Next: agree the durable journal/profile orchestration contract and test its crash
boundaries with fakes, retaining all NIC/phone/ownership requirements. Before live
use, isolated Keycloak tests must prove least-privilege denials, protected immutable
marker behavior, create policy/duplicate semantics, retained required actions,
enable/readback and action-email delivery. Trusted deployment TLS, action allowlists,
durable database adapters, rate limits and the reviewed orchestration remain gates.
No live endpoint or PostgreSQL provisioning is authorized by this adapter work.
